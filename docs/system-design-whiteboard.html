🧬 Estratégia composer + classifier — determinístico → LLM → determinístico

1 · mergeOrGroups (det.)
funde atoms com "or" na ordem da JD → EITHER-OR ("jest or vitest") resolvido sem gastar token de LLM
2 · keywordComposer (LLM)
jd_atoms × cv_chunks → 5–30 keywords {term, tier, variants} · guard isPlausibleVariant descarta variante não-literal antes de virar promessa de match
3 · keywordClassifier (LLM, payload pequeno)
verdicts só p/ keywords problemáticas: merge_into (OR quebrado em must-haves independentes) · strip_variant (variante que engole o token diferenciador) · reclassify (skill | eligibility | credential | seniority)
4 · applyKeywordVerdicts (det.)
aplica os vereditos por pós-processamento · LLM nunca inventa/drop/troca tier · falha do LLM → segue com mergeOrGroups puro
🛂 isPlausibleVariant — variante só se for superfície literal do termo
  • • concatenação dos tokens: nodejs ← node js
  • • tokens compartilhados ≥4 chars ou abrevs ≤3 chars fora de {web, app, dev, and, for, the}: ci cd ← continuous integration
  • • termo de 1 token + sufixo ≤3 chars: reactjs ← react · apis ← api
  • • rejeita: variante com mais tokens que o termo · qualquer sinônimo conceitual (semântica não credita score)
🎯 Por que esse desenho
  • • casos óbvios (OR explícito) resolvidos de graça — LLM entra só nos ambíguos, com payload pequeno
  • • variante literal é o contrato com o booleanMatcher: se o composer promete a variante, a busca word-boundary garante casar (zero falso prometido)
  • • LLM no papel de juiz (verdicts pontuais), não de autor — saída limitada, validável e com fallback
universalScore = min(100, 0.70·coverage + 0.15·content + 0.15·format + 0.05·niceBonus)
must ×3 · important ×2 · nice ×0 (fora do denominador, bônus cap +5) · −8/bullet genérico (cap −40) · −5/10% sem métrica (cap −30) · −12/seção vazia
✏️ /generate-resume (sync): re-executa extract→compose→gap no cache → draft GLM → verifier anti-fabricação (métricas rastreadas, Jaccard ≥0.2, frases genéricas → revert) → renderer + styleSanitizer → re-score; se piorar, 2ª draft e fica com a melhor. Jobs /analyze: Map em memória, 202 imediato, entrega por SSE (/result/:requestId/stream · heartbeat 15s · notificação por subscriber, fecha no terminal), sweeper 10min × TTL 30min. Cache: hash do conteúdo limpo → sem TTL/invalidação; warm = 3 LLM vs 5 frio.

7 · Trade-offs por camada

📦 Packages via fonte FRONTvs build/publicação de versões

  • Mutation instantânea: edita o package, o app já vê (HMR atravessa)
  • Zero overhead de build/registry no monorepo
  • Sem versionamento/semver — quebra silenciosa entre packages
  • TipTap pinnado exato (3.31.3) pra conter drift de peerDeps

🗄️ Query como fonte de verdade FRONTvs store global (Redux)

  • staleTime por domínio (CV 5min, ATS 30min, público 1h) mata refetch em loop de digitação
  • Chave inclui locale+JD → cache automático por combinação
  • ATS 30min pode servir report velho depois de editar o CV
  • Guard de rota lê localStorage (fonte paralela ao Context)

✍️ TipTap + Decorations FRONTvs textarea/Monaco diff

  • Sugestões inline clicáveis (insert/replace/remove) nativas do doc
  • Diff visual vs diffBase + flashes — UX de code review no CV
  • Serialização markdown↔ProseMirror é ponto frágil (normalização própria)
  • Duas experiências de editor mantidas (rich + Monaco fallback)

🔑 JWT stateless em localStorage APIvs sessões/httpOnly cookie

  • Verify O(1) sem I/O · serve web e chrome-extension igual
  • Logout client-side trivial (limpa storage no 401)
  • Revogação impossível por 7d (sem blacklist/refresh)
  • Token exposto a XSS (mitigado por helmet, sem sanitização de HTML)

💰 Cota debitada na tentativa APIvs cobrar só sucesso

  • Imune a flood: erro 502 não vira análise infinita grátis
  • Uma escrita no User por request — sem lock/atomicidade extra
  • Falha do agent consome cota do usuário (5/dia no free doem)
  • Reset à meia-noite no tz do servidor (UTC na VPS)

🧭 Dois cérebros de LLM API— GLM no agent, Gemini na API

  • Agente especializado em análise auditável; API cuida de prosa criativa com prompts ricos
  • Boundary claro: LLM só em llmService/atsService
  • Duas chaves, dois provedores, dois caminhos de custo/falha
  • linkedin-agent é um 3º caminho com poll diferente (no controller)

🧠 Jobs em Map + TTL AGENTvs Redis/BullMQ

  • Zero infra; 202 imediato desacopla caller de grafo de minutos
  • Entrega por SSE: 1 conexão, push no terminal — sem re-request de poll
  • Restart = jobs somem (API fica no stream aberto até 404/deadline)
  • Sem réplicas: job gruda numa instância · pending/running nunca expiram (leak)

🎯 Boolean matchmaking AGENTvs embeddings semânticos

  • Score reprodutível e auditável — toda keyword tem evidence literal
  • Espelha o ATS real (busca literal) · zero custo de embedding
  • Sinônimo conceitual não credita — depende do composer/classifier
  • Mitigação: gapAdvisor converte gap semântico em rephrase acionável

🗂️ SQLite content-hash AGENTvs Redis / sem cache

  • Invalidação por construção (hash do conteúdo limpo) — sem TTL
  • 5 → 3 chamadas LLM no warm (−40% custo/latência)
  • Local: não compartilha entre réplicas · WAL exige volume no Docker
  • Cresce sem eviction (reconstrível, mas ninguém reconstrói)

🛡️ Fallback determinístico por nó AGENTfail-fast

  • JSON quebrado do LLM nunca derruba o pipeline — sempre há report
  • Verifier anti-fabricação + re-score protege o resume gerado
  • Degradação silenciosa: gapAdvisor falho → tudo "absent" sem alarme
  • interviewPrep foge ao padrão (throwa → 502)

8 · Riscos & dívida técnica (post-its honestos)

🚨 Memory leak no agent

Jobs pending/running sem completedAt escapam do sweeper pra sempre. Um nó LLM travado (sem timeout) alimenta o leak.

⏰ Timeouts parciais

O stream api→agent agora tem deadline (AbortController, 5min) — mas Fastify e cliente OpenAI seguem no default (~10min). Nó LLM travado segura o stream aberto até o deadline.

💥 Report efêmero

ATSReport vive 30min no Map e não é persistido. Usuário fecha a aba = análise perdida (e cota debitada). Query do front cacheia, mas o cache é volátil.

🧬 Contratos costurados à mão

contracts (front) ≠ types.ts (agent) ≠ tipos da api. Drift é questão de tempo — a Opção C (todos importarem @jobapply/contracts) é o fix.

📐 Single-instance por design

Map de jobs + SQLite local impedem réplicas do agent. API escala, o cérebro não.

🧪 Testes assimétricos

Agent tem vitest por nó; api não tem teste nenhum (auth/limit/polling no escuro). Front testa painéis e helpers do editor.

🎭 Mock ligado por padrão

USE_MOCK !== 'false': qualquer dev esquece o .env e testa contra dados fake. O CI seta false, mas local engana.

📚 Resíduos legados

dist/ do agent com build antigo, swagger sem endpoints novos, docs/examples descrevendo arquitetura morta (gemini, platforms/).

📄 1 CV por usuário

unique em cvs.user; versões só via arrays embutidos (localeVersions/tailoredVersions) — doc cresce sem limite.

🧩 Extensão fora do repositório

apps/jobapply-extension não está commitada nem no CI (sem lint/testes); usa @jobapply/ui por hoisting sem declarar no package.json; host_permissions e fetch de auth com porta/portais hardcoded (3030).
