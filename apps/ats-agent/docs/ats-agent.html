ats-agent / boolean keyword matchmaking

Serviço Fastify + LangGraph + GLM que analisa um CV contra uma job description, pontua por busca booleana literal de keywords e gera dicas de rephrase para os casos de "mesma coisa, palavras diferentes".

porta 3001 LLM GLM · Z.ai índice node:sqlite orquestração LangGraph score 0.70 keyword · 0.15 conteúdo · 0.15 formato

01Visão macro

  • Nunca acessa o MongoDB — o único estado local é o SQLite de chunks, cache derivado e reconstruível dos inputs.
  • jobapply-api trata o relatório como unknown (pass-through): o contrato vive nos tipos do agente.
  • O score é estritamente booleano: sinônimo conceitual não pontua — vira dica de rephrase.

03chunk index (SQLite)

Os dois inputs enormes (CV completo e JD completa) são quebrados uma única vez em chunks cegos — átomos curtos, tipados e comparáveis. Todo o resto do pipeline consome só esses dados refinados, nunca os textos crus.

-- id = sha256(type :: attr normalizado) — acento/pontuação/case-insensitive
-- PK composta: o mesmo chunk pode pertencer a várias JDs/CVs
CREATE TABLE jd_chunks (
  id         TEXT NOT NULL,
  jd_id      TEXT NOT NULL,   -- hash do texto da JD (chave de cache)
  type       TEXT NOT NULL,   -- skill | tool | domain | credential | soft | req
  attr       TEXT NOT NULL,   -- o átomo (≤ 8 palavras)
  tier       TEXT NOT NULL,   -- must-have | important | nice-to-have
  created_at INTEGER NOT NULL,
  PRIMARY KEY (jd_id, id)
);

CREATE TABLE cv_chunks (
  id TEXT NOT NULL, cv_id TEXT NOT NULL,
  type TEXT NOT NULL, attr TEXT NOT NULL,
  section TEXT NOT NULL,          -- summary | skills | experience | ...
  created_at INTEGER NOT NULL,
  PRIMARY KEY (cv_id, id)
);

CREATE TABLE jd_meta ( jd_id TEXT PRIMARY KEY, job_title TEXT, created_at INTEGER );

Cache = pureza: chunks são funções puras do input (mesmo texto → mesmos chunks), então o cache é keyed por hash de conteúdo e sem TTL. Analisar o mesmo CV contra 10 JDs paga a extração do CV 1×. Em teste: CHUNKS_DB_PATH=:memory:.

04tipos principais

entrada e composição

interface AgentInput {
  cv?: CV                    // CV estruturado (JSON do Mongo)
  cvMarkdown?: string        // ou CV em markdown
  jobDescription: string
  locale?: 'en' | 'pt-BR'
}

interface ComposedKeyword {  // saída do keywordComposer
  term: string               // forma canônica, wording da JD, lowercase
  tier: 'must-have' | 'important' | 'nice-to-have'
  variants: string[]         // SÓ superfícies literais: "k8s", "nodejs", plurais
}                            // sinônimo conceitual NUNCA vira variante

interface KeywordMatch {
  term: string; tier: ChunkTier
  matched: boolean
  section: string            // onde casou; '' quando não casou
}

saída do gapAdvisor

interface GapAnalysis {
  rephraseGaps: RephraseGap[]   // "mesma coisa, palavras diferentes"
  absentKeywords: string[]       // sem evidência nenhuma no CV
  keywordPhrases: KeywordPhrase[]  // frases prontas só p/ absent
  removeSuggestions: RemoveSuggestion[]
}

interface RephraseGap {
  keyword: string           // keyword da JD que não casou
  cvPhrase: string          // como o CV diz hoje
  suggestedRewrite: string  // como reescrever com o termo exato da JD
}

contrato de saída (ATSReport) — imutável para api/frontend

interface ATSReport {
  universalScore: number              // 0-100
  scoreBreakdown: {
    keywordCoverage: number          // booleano ponderado por tier
    contentQuality: number           // genéricas + densidade de métricas (regex)
    format: number                   // seções obrigatórias + períodos (regex)
  }
  matchedKeywords: string[]
  missingKeywords: string[]
  semanticGaps: string[]             // hoje: dicas de rephrase em texto
  optimalTemplate: {
    sectionsOrder: string[]
    keywordsToAdd: string[]          // só os truly-absent, ordenados por tier
    keywordPhrases: KeywordPhrase[]
    keywordsToRephrase: { from: string; to: string }[]
    formatFixes: string[]
  }
  tips: { priority: 'critical' | 'high' | 'medium'; tip: string }[]
  removeSuggestions: RemoveSuggestion[]
}

05modelo de score

keyword 0.70
conteúdo 0.15
formato 0.15
bônus de nice-to-have: +5 no máximo, só soma, nunca penaliza
TIER_WEIGHT  = { 'must-have': 3, important: 2, 'nice-to-have': 0 }

// keywordCoverage = soma dos pesos casados / soma dos pesos obrigatórios
universalScore = min(100,
    0.70 × keywordCoverage
  + 0.15 × contentQuality      // frases genéricas -8 · métricas < 40% dos bullets
  + 0.15 × format               // seção faltante -12 · período ausente -10
  + niceToHaveBonus × 0.05
)

matching literal (booleanMatcher)

  • norm() compartilhado: NFD → lowercase → pontuação vira espaço → trim
  • word-boundary regex — go não casa dentro de django
  • plural/singular no último termo — rest api casa rest apis
  • term + variants — node js casa Node.js (pontuação normalizada)

guardas do resume (verifier, 0 token)

  • metric-dropped / metric-invented — todo número do original tem que continuar
  • low-overlap — reescrita com Jaccard < 0.2 volta ao original
  • generic-phrase — AI-smell ("leveraged", "responsible for") rejeitado
  • invalid-source — sourceIndex fora do range/duplicado descartado

Regra de ouro: semântica não credita score. Se o CV diz "component library development" e a JD pede "design systems", o coverage não sobe — a falta vira uma dica keywordsToRephrase. O score só melhora quando o candidato reescreve de verdade. É o que um ATS real faria.

08decisões de design

  1. Booleano estrito, sem crédito semântico. Score espelha o que um ATS real faz; semântica vira conselho, não pontuação.
  2. Chunks cegos como única representação. Composição, matching e dicas operam sobre átomos tipados — os textos crus só entram nos extratores.
  3. Cache sem TTL. Chunks são puros; hash de conteúdo + INSERT OR IGNORE. Invalidação natural: muda o input, muda o hash.
  4. Variantes ≠ sinônimos. "k8s" é variante de "kubernetes"; "cloud" não é. O rephrase existe justamente para o caso conceitual.
  5. Guardas determinísticas > validação LLM. Verifier, sanitizer e fallbacks locais são gratuitos e determinísticos; LLM só onde há julgamento (extrair, compor, aconselhar, redigir).
  6. Contrato estável. ATSReport manteve a mesma forma consumida pelo frontend (universalScore, 3 categorias de breakdown, optimalTemplate, tips) — jobapply-api não precisou de mudança.
